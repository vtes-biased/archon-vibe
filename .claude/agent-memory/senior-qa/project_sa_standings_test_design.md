Testing SA (standings_adjustment) effects on standings/ratings. Three non-obvious facts that bit while building the #472 regression test (`test_sa_on_soft_cancelled_round_penalizes_vp_and_gw_together` in `engine/src/tournament/tests.rs`).

**Single shared resolver — test the invariant ONCE.** `resolve_sa_effective_rounds` (sanctions.rs) is the SINGLE source both SA consumers read: `sa_vp_penalty` (VP total, applied unconditionally) and `table_sa_adjustments` (per-table GW/TP cascade). The #472 divergence class lives in the asymmetry — the VP penalty is unconditional but the GW/TP loops `continue` past Cancelled tables (standings.rs:47, :322). Both `compute_preliminary_standings` and `compute_rating_vp_gw` call the same resolver, so a resolver fix covers both. Don't write a `compute_rating_vp_gw` twin of a `compute_preliminary_standings` SA test — same invariant, redundant.

**`gw` is the discriminator; `vp` doesn't move.** For an SA test that must fail pre-fix on the GW/TP side: `vp` is often equal pre- and post-fix (the VP penalty is unconditional, and a Cancelled round is skipped in the VP sum either way), so `gw` (and TP re-rank) is the only value that flips. Name `gw` as the pre/post witness in the comment; assert `vp` only as documentation.

**GW threshold is `>= 2.0` INCLUSIVE (5-seat table).** `compute_gw` (scoring.rs), pinned by `test_gw_with_sa_still_above_threshold` (raw 3.0, −1 → adjusted 2.0 KEEPS the GW). So when `gw` discriminates, the penalized player's raw VP must be in `[2.0, 3.0)`: clears 2.0 at 0 adjustment (pre-fix keeps GW) and drops below at −1 (post-fix removes it). Raw 3.0+ retains the GW even at −1 → test goes green both ways → a relic. Canonical safe vector: `[2.5, 1.0, 0.5, 0.5, 0.5]` (sum 5, engine-valid).

**Finals SA = round index `nrounds` (the SetScore sentinel).** `resolve_sa_effective_rounds` now scans the finals table as round `len(rounds)`; `compute_preliminary_standings` filters those out of the prelim VP penalty (finals SAs hit the finals GW/winner + rating VP, never prelim rows). `update_standings` → `refresh_finals_scoring` re-scores a `Finished` finals from raw VPs + current active sanctions and re-derives `winner` via the same `compute_gw_finals` SetScore/FinishFinals use. Because that recompute reads *current active* sanctions from scratch every call, **issuing and lifting a finals SA are the same code path** (lift just drops it from `get_sa_sanctions`) — the issue-direction test (`test_finals_sa_rescores_finals_and_rederives_winner`, engine tests.rs) IS the invariant; a lift-direction twin is redundant (no new branch). FinishFinals-with-a-pre-existing-finals-SA shares `compute_gw_finals`+`table_sa_adjustments` too — same invariant, verify that live flow manually rather than duplicating. Backend `round_number == len(rounds)` is accepted only when `tournament.finals` exists (sanctions.py create/update); the reject half guards a value the UI (`if (tournament.finals)`) can't produce, and the accept half needs a heavy engine-valid finished-finals fixture to reach — see [[sanction-update-test-infra]], don't build it.

**Reaching a Cancelled round: cancel a NON-LAST round.** `CancelRound` (mod.rs) soft-cancels (marks tables `Cancelled`, KEEPS the slot + seating) only for a non-last round; cancelling the LAST round hard-removes it — so no Cancelled table ever appears in the JSON. An SA-on-cancelled-round test must therefore use a ≥2-round tournament and cancel round 0 (state Playing/Finished; Waiting is rejected). The preserved round-0 seating is what keeps the SA's `round_number` tag resolvable and the player seated in the cancelled round (the exact pre-fix trigger). See also [[engine-test-fixture-traps]].

# Internationalization

Five locales: **en** (British, the source), **fr**, **es**, **pt** (pt-BR), **it**.
Paraglide JS (inlang), client-only — the SPA has no SSR. A Vite plugin compiles
`frontend/messages/*.json` into TypeScript used as `m.key_name()`. Browser
auto-detection with cookie persistence, plus a manual switcher in profile settings.

Term equivalents live in [glossary](glossary.md); this page is how to work the
files.

## Infrastructure

Flat JSON, one key per string, **no plural or interpolation system** — English copy
must hand-pluralize (`{count} round(s)`). Key order in every locale follows
`en.json`: insert a new key immediately after the same preceding key as in the
source. `en.json` exceeds the single-read limit, so extract keys with `python3` or
read with offset and limit.

Key prefixes: `nav_`, `profile_`, `help_`, `common_`, `offline_`, `checkin_qr_`;
`tournament_`/`tournaments_` with sub-sections `rounds_`, `finals_`, `decks_`,
`players_`; `sanction_`/`sanction_mgr_`; and the help guides `pg_` (player guide)
and `og_` (organizer guide, with `og_cfg_` for config and `og_faq_q_`/`og_faq_a_`
for the FAQ).

**Workflow**

1. Find missing keys by diffing the loaded JSON against `en.json`.
2. Build a translations dict, update, and write with `ensure_ascii=False, indent=2`
   plus a trailing newline.
3. Validate the JSON parses.
4. Compile with paraglide, then `npm run check`.

**Inserting a cluster: do not rebuild the file in `en.json` key order.** Some
locale files carry a small pre-existing order drift in unrelated spots. A full
rebuild "fixes" that as an unwanted side effect and produces a diff touching
unrelated lines. Instead iterate the locale file's own dict, copy every key through
unchanged, and splice the new cluster in right after its anchor key — first
confirming the anchor is adjacent to the following key in the *locale* file too.
Verify with `git diff --stat` showing zero deletions before compiling.

**Editing one paragraph inside a long markdown string**: split on `\n\n` to get
numbered segments, replace the target index, and rejoin. The segment split is
stable across locales because structure mirrors the source even when wording
differs — safer than multi-line string matching.

**Concurrent writers are real.** Editing all five files and immediately running
`git diff` has shown different, unrequested text in place of what was just written,
including `en.json` reverted to stale wording — another process writing the same
keys. **Always re-read the just-written key from disk immediately before running
codegen or reporting done.** An Edit tool success only proves the write landed at
that instant.

**The English source can change mid-task**, including keys already handed to you.
When a mismatch between prose and the live UI is flagged, re-pull that key's
*current* `en.json` value before redoing it — the source itself may have moved.

## The changelog

`CHANGELOG.md` is **not** translated. The "what's new" modal
([architecture](architecture.md#whats-new)) translates its shell — the title and
the close button — and renders the entries as authored, in English.

Translating them would put a five-locale pass on the critical path of every
release, and its failure mode is a modal half-translated on the day it ships. The
precedent is `help-content/`, where four locales read the judge's guide in English.
Do not add a `CHANGELOG.<locale>.md`.

## Register

Semi-formal throughout, no slang. Official VTES game terms use Black Chantry
rulebook translations; flag an uncertain term for human review rather than coining.
Organizer and management UI — offline session, force-unlock, takeover — uses plain
administrative language with no game flavour.

Form of address: **fr** vouvoiement, **es** usted, **pt** você, **it** mixed.
Italian player-facing action UI is informal *tu*, while the offline and
organizer-administrative block uses formal **Lei**; `admin_*` is *tu*, not Lei. And
`es.json` is usted by default file-wide but has whole sections consistently *tú* —
the profile/community block, and the VEKN-sponsor/add-player block.

**Always check the immediate sibling keys, not a file-wide word count.** A global
"usted is dominant" count can still be wrong for the section you are editing. The
same rule applies to fr and pt.

**Button-label mood**: fr/es/pt use the **infinitive**, it uses the
**tu-imperative**, regardless of the surrounding register — including `<a>` links,
`title=` and aria-labels styled as actions. Running body text uses each locale's
normal conjugated imperative. Confirm titles ending in "?" take the infinitive plus
"?" in all four whatever the file register; titles without "?" use the Italian
imperative. Descriptive prose sidesteps register entirely with impersonal third
person.

**Quoting a UI feature or button inline**: wrap in the locale's own quote marks —
fr `« text »` with **regular U+0020 spaces**, not NBSP; es/it `«text»` with no
spaces; pt curly `"text"`. For third-party product features use that product's own
localized term, not a literal translation. But **mirror the source**: if English
quotes it, quote; if not, don't. The "Use [ButtonTerm] for X" shape is always
unquoted.

## Conventions

**Bold only what English bolds.** A named tab bolds its key's word; the generic
phrase stays unbolded. Never emphasize a term the source doesn't, even if it is a
real button label. When English changes markup — from `"Checked-in"` to
`**Checked in**` — every locale swaps quotes for bold.

**Match live UI labels, not guide prose.** The recurring bug class is guide copy
drifting from the real displayed text. When guide copy bolds a state name or a
button label, look up the actual `state_*` / `*_btn` / `*_title` value — do not
trust the guide, or `en.json`'s own prose, which has itself been wrong. This is
worth re-checking even in prose you already translated correctly once; a later
sweep found four more mismatches across eight keys after the first was flagged.

**Precedent order when coining**

1. Grep the richest precedent first — a `pg_*` or `og_*` guide body explaining the
   same concept outranks the glossary table.
2. Check sibling keys in the cluster before any file-wide default; the local
   sibling wins.
3. Same term, same translation inside a new cluster, even where the wider file is
   inconsistent.
4. When English switches verb mid-string, mirror the switch instead of normalizing.
5. Coin only when a full-file grep finds nothing.

**Document cross-references** — the in-app markdown renderer resolves "see …"
references by heading lookup. Spanish *véase* references prefix the target title
with a section word that must be stripped before the lookup while staying in the
visible link text; the preprocessing lives in `markdown.ts`.

**Anchors** — fr/es/pt always keep English slugs. Italian localized them
historically and untouched old keys still do, but retranslated keys use bare
English slugs while headings stay translated. Don't retrofit old keys; if unsure,
check whether the anchor's *target* heading was retranslated.

**Punctuation** — fr uses a regular ASCII space before `:` and `;`, not a
typographic NBSP. Digit runs, ellipses and em dashes are not translated content;
mirror the source rather than normalizing. On a partial source change, retranslate
only the changed clause.

**Number and gender** — count markers are `joueur(s)` · `jugador/es` ·
`jogador/es` · `giocatore/i`; fr/es/pt lean to `(s)`, it to the slash, and Italian
never adds -s. Where the Italian noun is invariable but its adjective isn't, mark
only the adjective. Verbs in dynamic-count sentences default to plural
unconditionally — a pragmatic compromise. Unqualified participles default to
masculine singular. A round ordinal mid-sentence is lowercase. Singular English
"they" is worked around with an explicit demonstrative noun.

**Callouts** — NOTE · NOTA · NOTA · NOTA; TIP: CONSEIL · CONSEJO · DICA ·
CONSIGLIO; Warning: AVERTISSEMENT · ADVERTENCIA · — · ATTENZIONE.

## Per-locale traps

**fr** — translates Constructed/Limited, "ranking" → *classement*, "casual" →
*décontracté*; keeps "console" bare where es translates it. Regular ASCII space
before `:` and `;`. "(optionnel)", never "(facultatif)". Sanction levels are
counter-intuitive. No record-versus-save split. Four distinct check-in word
families.

**es** — reverses to "ID VEKN" where the others keep "VEKN ID". Uses a
hay-construction for "no X recorded/found", never a bare *ningún*. No
remove-versus-delete split (*eliminar* covers both) and no link-versus-attach split
(*vincular* covers both). "venta de entradas" spelled out, not a loanword. Leísmo
*añadirle* for unknown gender. "Rondas autoorganizadas" without a hyphen.

**pt** — pt-BR is the convention: *celular*, *rodada*, *cronômetro*, *baixar*,
*links compartilhados*, *padrão*. Never reintroduce European forms. *estoque* not
stock; *pontos de classificação* not *de rating*; *Hall da Fama*; *movimentação*
for a ledger row; *com falha* for failed. No distinct attach verb.
`tfield_rank` is *Categoria*, not *Classificação*, which is held by standings.
In guide prose, bold `og_*`/`pg_*` spans are reconciled with their English
counterparts, but non-bold literal-English strings may remain — grep before
relying on one.

**it** — never pluralizes English loanwords; slash-marks adjectives, not nouns;
*segnare* not *marcare*; TWDA is masculine in one key and feminine in another, an
unreconciled gap; Lei only in the offline and force-takeover block; omits the
possessive on "la fotocamera"; carries an unreconciled *idoneo*/*eleggibile* split;
localized anchor slugs survive in older keys only.

## Known gaps — found, not reconciled

Don't silently unify these.

- French splits the override verb cluster (*Modifier*) from help-guide prose that
  historically used a different noun; the concept noun is now *modification* to
  match, but check all three override keys together whenever the noun recurs.
- `rooms_title` disagrees with the guide's own name for that section in several
  locales.
- `tfield_open_rounds` versus the guide's wording is reconciled in fr and not in
  it. Always match the real field label.
- The TWDA full name is a three-way split: it keeps English, fr paraphrases, es/pt
  translate. Don't fix one without the others.
- French `raffle_clear_confirm` still uses the long form where `raffle_clear` uses
  the short one.
- The GP points formula is stated from different ends by two keys. Both are
  accurate; translate each as written. **Not a bug — do not "fix" it.**

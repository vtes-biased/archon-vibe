# Board

A list designed to shrink. **The goal is zero.** Completion is deletion — there is
no closed state, no archive; git history is the record and `git blame` knows a
line's age.

**Order is priority.** Ranking rules, applied top to bottom when two unrelated
lines compete:

1. user-reported defects
2. correctness
3. blocking work and useful refactorings
4. polish
5. new capability

**Hard limit: 15 lines.** Adding a sixteenth forces a drop or a promotion to the
wiki. **No waiting state**: externally-gated work is deferred on the wiki page
that owns it — see [wiki/vekn-decommission.md](wiki/vekn-decommission.md) — with a
named trigger, and returns through `/intake` when the trigger fires.

**Every line must be completable** — if "done" cannot be stated, it is a subject:
promote it to a [wiki](wiki/index.md) page and delete the line. Context lives in
the wiki; asks live here. Bulky context for an in-flight line goes in
`board/<slug>.md`, deleted with the line.

Board changes ride the commit that earns them.

- Let the tournament page notice the corpus arriving — `frontend/src/routes/tournaments/[uid]/+page.svelte:626` listens only for a live `tournament` event, never for `sync_complete`, but the whole-corpus snapshot ingest emits no per-object events, so a page that mounted against an empty IndexedDB sits on the blocking `tournament_error_not_synced` gate (`:439-440`, rendered at `:653-660`) until an unrelated edit happens by or the viewer reloads. Signing in guarantees that empty store — `syncManager.refresh()` clears and refills (`frontend/src/lib/sync.ts:666-673`) from six call sites in auth. Eleven surfaces already handle it, including the tournament list next door (`frontend/src/routes/tournaments/+page.svelte:260`) and `frontend/src/routes/t/[code]/+page.svelte:29`, whose comment names this exact trap; reloading mid-ingest also discards the partial corpus, so against a ~13MB gzip download (`wiki/sync.md:593`) only the attempt that outlasts it wins. **Done when** the page renders itself as soon as the corpus lands with no reload, the wait reads as progress rather than an error, and `wiki/sync.md` carries the invariant that any surface reading IndexedDB at mount must listen for `sync_complete` — the rule that stops a twelfth surface repeating this. gh-18.
- Show an already-registered player in the add-player search instead of hiding them — `frontend/src/lib/components/AddPlayerForm.svelte:46-47` filters every registered uid out of the results, so an organizer searching for someone already on the roster gets an empty dropdown whose only entry is the bolded "Player not on Archon?" create button (`:153-161`); it reads as the reason for the empty result and invites creating a duplicate account that only an IC can merge back (`wiki/product.md:51`). The row treatment already exists — keep them listed but disabled with an inline reason, exactly as a suspended member is rendered at `:118-144`, reusing the already-translated `err_tournament_already_registered` (`frontend/messages/en.json:1618`, `frontend/messages/es.json:1618`). **Done when** searching for a registered player shows them greyed and marked already registered rather than an empty list, the create affordance is no longer the only thing on screen when a match exists, and no new message key is introduced. gh-14.
- Make a player's device await the server before it reports an outcome — a player's device can never hold the offline lock (`wiki/architecture.md`, online and offline), so the optimistic path buys it nothing, yet `DeckUpload` sets `success` and renders "Deck uploaded" (`frontend/src/lib/components/DeckUpload.svelte:221`, `:366`) off the local result while `tournamentAction` has merely enqueued the POST (`frontend/src/lib/tournament-actions.ts:142-163`) — which reported a success the server refused, and, when a phone locked before the queue drained, lost a deck in silence while still showing it to its owner. Keep the WASM call as a pre-flight and await the round-trip on every player-initiated action — register, check-in, own-table VP report, deck upsert and delete — so the server's reason lands in the surface's own error slot instead of a detached toast. The organizer console keeps the optimistic path. **Done when** no player-side surface reports an outcome the server has not granted, a refusal is explained where the player acted, the console's optimistic path is unchanged, and the E2E waits keyed on optimistic behaviour (`wiki/testing.md:95-99`) move with it. gh-12, gh-16.
- Restore the member list the way the viewer left it — `/users` never mirrors its tab to the URL (`frontend/src/routes/users/+page.svelte:23-29`; the tab buttons at `:52`/`:59`/`:66` write nothing back), so browser Back from a member profile lands a filtered viewer on the Community tab, and the two sanction toggles are held in component state alone (`frontend/src/lib/components/UserList.svelte:61-62`) under a comment calling them officials-only (`:49-50`) when their controls render at `:433-452`, outside the `{#if isOfficial}` guard at `:455`, for every signed-in viewer. Mirror the tab the way `/rankings` already does (`frontend/src/routes/rankings/+page.svelte:107-113`) and carry the sanction toggles with it; sponsor and no-VEKN are genuinely officials-only and stay out of the query string. **Done when** a Prince who filters the member list to sanctioned players, opens a profile and hits Back returns to the Members tab with every filter still applied, a shared `/users` URL carries no sponsor or no-VEKN filter, and the list-view-state section of `wiki/design.md` records which filters are excluded and why. gh-11.
- Put the drafted question set to the Rules Director on no-final tournaments and record the answer — our engine is rules-literal and awards no winner or finalist rating without a played final, while vekn.net credits a no-final top five exactly like a final. The question that matters most to us is the one the rules do not cover: whether an event that lost its final to force majeure rates at all, since we allow a no-final finish at any size. **Done when** the answers are in `wiki/domain/`, either the engine changes or the no-final note in `wiki/tournaments.md` cites the ruling, and the archon-file importer — which today crowns the top preliminary seat where the engine crowns nobody — is reconciled with it. Context in `board/no-final-rating.md`.
- Give the organizer console's action queue a durable outbox — with player-side actions now awaiting the server, what remains is the console's own online path: the POST sits in an in-memory promise map (`frontend/src/lib/tournament-actions.ts:31`) with no persistence, no unload flush and no replay on launch, so a judge's phone locked or a tab closed between the optimistic IndexedDB write and the POST drops the action silently — no request, no rollback, no error, and no SSE frame will ever correct it. The durable half already exists for offline events (`frontend/src/lib/db.ts:1123-1127`, `frontend/src/lib/tournament-actions.ts:118-123`); the online console needs the same. **Done when** a console action interrupted by a reload, a lock or an app kill is replayed on next launch instead of dropped, and the mutation-pipeline section of `wiki/architecture.md` states that the owning device's queue is durable.
- Stamp `bd.org_uids` when an account merge reassigns a deck — `backend/src/accounts.py:63-79` `reassign_decks` returns its `BroadcastData` without the organizer stamp every other deck save path sets (`backend/src/routes/tournaments.py:183`, `:197`, `:207`, `:218`, `:534-555`, `:2408-2410`, `backend/src/twda_import.py:443-444`), and a deck carries no `organizers_uids` of its own for the broadcast to infer one from (`backend/src/db.py:379`, `wiki/sync.md:304-306`). The frame therefore projects at member level, where `compute_deck_member` returns `None` for a non-public deck (`backend/src/access_levels.py:218-221`), and the reassigned deck stays invisible to the tournament's organizer until their next reconnect replays the personal overlay. **Done when** a deck moved by an account merge reaches the organizer on the same frame as every other deck write, and the deck-broadcast note in `wiki/sync.md` names the merge among the paths that must stamp it.
- Put the deck URL and QR import behind `authorizedFetch` — `frontend/src/lib/deck-fetch.ts:20-26` calls `fetch` with a hand-attached bearer rather than the wrapper every other authenticated call uses (`frontend/src/lib/api.ts:50-55`), so this path alone has no 401-refresh-and-retry: a player whose access token expired while the app sat open at the venue gets a hard failure where pasting the same list would have worked. The server's actual reason is swallowed to the console at `deck-fetch.ts:29` and the player is shown the one generic `deck_url_import_failed`, so an expired session, an unsupported link and a provider outage are indistinguishable. **Done when** URL and QR import inherit the same refresh-and-retry as every other authenticated call, and a failed import says which of those three happened.

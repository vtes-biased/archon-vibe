# Board

A list designed to shrink. **The goal is zero.** Completion is deletion — there is
no closed state, no archive; git history is the record and `git blame` knows a
line's age.

**Order is priority.** Ranking rules, applied top to bottom when two unrelated
lines compete:

1. user-reported defects
2. correctness
3. blocking work and useful refactorings
4. polish
5. new capability

**Hard limit: 15 lines.** Adding a sixteenth forces a drop or a promotion to the
wiki. **No waiting state**: externally-gated work is deferred on the wiki page
that owns it — see [wiki/vekn-decommission.md](wiki/vekn-decommission.md) — with a
named trigger, and returns through `/intake` when the trigger fires.

**Every line must be completable** — if "done" cannot be stated, it is a subject:
promote it to a [wiki](wiki/index.md) page and delete the line. Context lives in
the wiki; asks live here. Bulky context for an in-flight line goes in
`board/<slug>.md`, deleted with the line.

Board changes ride the commit that earns them.

- Give the top-level surfaces module-level projections instead of re-reading the corpus. Listing fifty tournaments deserializes all 9,563 of them — ~62MB of heap and 1.3s — and the list re-runs that on every filter, page and search change with nothing stopping a newer read stacking on one still in flight; six overlapping reads measured 385MB of JS heap, which is what puts the tab in the hundreds of megabytes. Keep a lean list-view map per corpus, maintained inside the store's own save, delete and clear so every writer feeds it and not just the sync stream, and read IndexedDB by key only when a detail surface needs the whole object. Projections measure 2.4MB for tournaments and 2.2MB for members against 64.6MB and 18.7MB full. This makes memory-resident projections a sanctioned read source, so amend the offline-first dogma to say reads come from IndexedDB directly or through a projection over it, never from the network. **Done when** no top-level surface reads a whole store, the list's heap stays flat across a minute of filter flicking on the production corpus, the amended dogma is in `wiki/dogmas.md`, the projection shapes are in `wiki/sync.md` beside the user-index note, and `wiki/hazards.md` carries the rule that every writer of a store maintains its projection. Context in `board/list-projections.md`.
- Put the drafted question set to the Rules Director on no-final tournaments and record the answer — our engine is rules-literal and awards no winner or finalist rating without a played final, while vekn.net credits a no-final top five exactly like a final. The question that matters most to us is the one the rules do not cover: whether an event that lost its final to force majeure rates at all, since we allow a no-final finish at any size. **Done when** the answers are in `wiki/domain/`, and either the engine changes or the no-final note in `wiki/tournaments.md` cites the ruling. Context in `board/no-final-rating.md`.
- Finish the production cutover's post-flip steps: install the Discord bot on the production guild(s), set the portal redirect URIs, ToS and privacy URLs and the Linked Roles Verification URL for archon.vekn.net, then run the improved dedup on production (`--probe-vekn`, review, `--apply`) and tell the waiting organizer his event can be finished. **Done when** the bot is installed, the portal is configured, the dedup is applied and the organizer has been contacted. Context in `board/prod-migration.md`.
- Decommission legacy archon: final `pg_dump` archive of `archondb`, remove the `archon_web` systemd unit, archive the old repository read-only, cold-store the `tournament_events` dump, and retire the `new.` hostnames — the hand-edited 302 vhost, its certbot cert and its DNS A record, on both archon.vekn.net and krcg.org. **Done when** none of those exist and the archive is stored. Context in `board/prod-migration.md`.
- Put the public API online on beta: the daemon grant, the `public_api` ansible role, its cert and its throttled vhost are written and unrun, so what is left is the `api.archon.krcg.org` A record, a full (not quick-lane) beta deploy, and the verification — register an `api:read` client, mint a daemon token with it, read one full refresh unthrottled, see a tight loop of them refused with 429, and see the same token rejected by the app. **Done when** the beta API answers a daemon token and the throttle has been observed. Context in `board/public-api.md`.
- Hand the card catalog to the engine once instead of per validation. Every deck validation rebuilds the whole 1.7MB card catalog into a JSON string and re-parses it inside the engine, and a tournament's players tab does that once per player — a hundred-player event pays a hundred rebuilds and re-parses of an identical, immutable catalog. Hold the parsed catalog in the engine and pass a deck alone. **Done when** validating a tournament's decks serializes the catalog at most once per session, and `wiki/hazards.md` records that an argument handed to the engine permanently sizes its linear memory at roughly eight to ten times the argument's JSON, because WebAssembly memory grows and never shrinks.
- Collapse `LinkModeration` to a single stored state. It keeps `status`, `scope`, `by` and `at`, but the real value space is three: hidden, promoted nationally, promoted globally. `scope` is meaningless when the status is hidden, and `by`/`at` are an audit trail nothing in the app reads back. Replace the struct with one enum across the engine, the backend, the frontend and stored links, and log who moderated and when instead of storing it. **Done when** a link carries one moderation value, no audit field survives in any projection, and `wiki/architecture.md` records the shape.
- Rename the `Judgekin` role to the name the product already shows, `Sheriff`. `frontend/src/lib/roles.ts` records why it was deferred: renaming meant migrating user rows during the live parallel run. That run ends with the decommission line above, so the gate is lifting. The literal is in the engine's `Role`, the backend enum and the Discord roles hook's level map, plus every stored user row. **Done when** no `Judgekin` literal remains, the row migration is written and wired into the deploy path, and `wiki/access.md` and `wiki/post-deploy.md` carry it.
- Say what the stored fields mean. The public API documents its published fields by hand in `schemas.py` because the models carry bare types: a `dict[str, int]` never says what keys it holds, a country never names ISO 3166, a language never names ISO 639-1, and a sentinel like `TournamentRank.BASIC = ""` reads as a missing value. Sweep `models.py` under the same light and let the API's hand-written descriptions collapse into whatever the models can express. **Done when** every dict-typed, date-typed and code-typed field in `models.py` names its key meaning or its standard, and no description in `schemas.py` restates something the model now says.
- Restore `POST /oauth/revoke` (RFC 7009, removed in `3abb708`) so a third party can hand back a user's `oauth_access`/`oauth_refresh` pair without the user going to their profile — the wiki deferred it on "the daemon grant lands", which it now has. A  token is stateless and out of scope: there is nothing to revoke but the client's `active` flag. **Done when** the endpoint revokes a live token pair, an unknown token stilldaemon answers 200 per the RFC, and `wiki/access.md` lists it.
